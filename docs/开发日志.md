### 详细改动

**`robot/ws_client.py`**

1. 新增常量：
   - `HOME_POINT = {"x": 0.0, "y": 0.0, "yaw": 0.0}`：本地默认原点（没收到 Windows 下发的 `home` 时才用）。
   - `NO_RETURN_POINTS = ("home", "charge")`：这两个点本身不回原点。
2. `NavController`：
   - 新增 `self.home`，可由 Windows 下发的 `home` 覆盖。
   - `goto(x, y, yaw, go_home=False)`：到点后是否回原点。
   - 拆出 `_drive(x, y, yaw, token, fail_msg)`：发一个目标点并等结果（原来 `_goto_thread` 的导航部分）。
   - `_goto_thread` 流程：先去目标点 → 成功报 `arrived` → 若 `go_home` 则报 `{"state":"moving","point":"home"}` → 回原点 → 成功报 `{"state":"arrived","point":"home"}`。
   - `_report(state, message, point=None)`：支持指定上报的点位（返回原点时 point 为 `"home"`）。
3. `CarClient.handle_message`：
   - 解析 Windows 发来的 `"home": {...}`，更新 `self.nav.home`；
   - `go_home = point not in ("home", "charge")`；
   - 打印日志「到达后返回原点 / 不回原点」。
4. `CarClient.on_nav_status`：状态里的 `point` 优先用回调带的值（返回原点时显示 `home`）。

**`frontend/ws_serer.py`**（2 行以内）

- `send_nav` 发的 `nav` 消息增加 `"home": HOME_POINT`，原点坐标只在前端维护一份，小车端不用重复配置。

## 2026-11-18 第 6 轮（本轮）：修复首次 push 被拒（unrelated histories）

### 问题

用户执行 `git push -u origin main` 报错：

```
! [rejected] main -> main (fetch first)
hint: Updates were rejected because the remote contains work that you do not have locally.
```

### 原因

- 远程仓库（`git@github.com:Rynkio-dot/auto-project.git`）是 GitHub 网页新建的，自带一个 `Initial commit`（只有 `LICENSE`）。
- 本地是 `git init` 独立初始化的（只有一个 `第一次提交`）。
- 两边历史没有共同祖先（unrelated histories），所以不能直接 push。

### 处理

```bash
git fetch origin
git merge origin/main --allow-unrelated-histories -m "合并远程仓库初始提交"
git push -u origin main
```

合并无冲突（只是把远程的 `LICENSE` 合进来），push 成功：

```
653ef63..c88ffc1  main -> main
```

当前 `main` 已跟踪 `origin/main`，以后直接 `git push` 即可。

## 2026-11-18 第 7 轮（本轮）：push 报 DNS 解析失败

### 问题

```
ssh: Could not resolve hostname github.com: Name or service not known
fatal: Could not read from remote repository.
```

### 原因

不是 Git 配置问题，是当时电脑的网络 / DNS 解析不了 `github.com`（网络闪断或切换）。
几分钟后复测：

- `ping github.com`：通，约 80ms
- `ssh -T git@github.com`：`Hi Rynkio-dot! You've successfully authenticated`
- `git push`：`Everything up-to-date`

说明网络恢复后仓库已经是最新的，无需任何修复操作。

### 处理

网络恢复后直接 `git push` 重试即可；以后遇到可依次执行：

```bat
ping github.com
ssh -T git@github.com
nslookup github.com
ipconfig /flushdns
```

仍解析失败就换公共 DNS（8.8.8.8 / 114.114.114.114）或重连网络/VPN。
