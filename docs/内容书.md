# 内容书：Git 同步 / clone / push

> 仓库地址：`git@github.com:Rynkio-dot/auto-project.git`
> 这份文档只讲 Git，项目怎么跑看 `README.md`。

---

## 1. 第一次：把仓库 clone 到本地

```bash
git clone git@github.com:Rynkio-dot/auto-project.git
cd auto-project
```

- `git@github.com:...` 是 **SSH 地址**，需要先把电脑的 SSH 公钥加到 GitHub。
- 不会配 SSH 就用 **HTTPS 地址**：

```bash
git clone https://github.com/Rynkio-dot/auto-project.git
```

第一次 push 会弹窗让你登录 GitHub。

> 已经有这个文件夹了（比如从 U 盘拷过来的），就不用 clone，直接 `cd auto-project` 然后跳到第 3 节。

---

## 2. 配置身份（每台电脑只做一次）

```bash
git config --global user.name "你的名字"
git config --global user.email "你的邮箱"
```

邮箱最好和 GitHub 账号一致。

---

## 3. 日常同步：pull → 改 → add → commit → push

### ① 先拉一下最新代码（别人可能改过）

```bash
git pull
```

### ② 看自己改了哪些文件

```bash
git status
```

### ③ 把改动加入暂存区

```bash
git add .            # 全部加入
# 只加某个文件：git add frontend/ws_serer.py
```

### ④ 提交（写清楚改了什么）

```bash
git commit -m "改了内容书写法"
```

### ⑤ 推到 GitHub

```bash
git push
```

> 第一次 push 如果提示没有上游分支，用：
> `git push -u origin main`

---

## 4. 常用查看命令

```bash
git log --oneline -5       # 最近 5 条提交
git diff                   # 还没 add 的改动
git diff --staged          # 已经 add 的改动
git remote -v              # 看远程仓库地址
```

## 5. 本地和远程冲突了（pull 失败 / push 被拒）

### 情况 A：push 被拒（远程有你本地没有的提交）

```bash
git pull            # 先合并远程
# 如果没冲突，再
git push
```

### 情况 B：pull 提示冲突（CONFLICT）

1. 打开提示冲突的文件，会看到：

```
<<<<<<< HEAD
你本地的代码
=======
远程的代码
>>>>>>> origin/main
```

2. 手动改成你想要的样子，**把 `<<<<<<<`、`=======`、`>>>>>>>` 三行删掉**；
3. 然后：

```bash
git add 冲突的文件
git commit -m "解决冲突"
git push
```

### 情况 C：本地改乱了，想丢掉所有没提交的改动

```bash
git checkout -- .        # 谨慎！没提交的改动会没了
```

### 情况 D：第一次 push 被拒 `fetch first` / `unrelated histories`

远程仓库是在 GitHub 网页上新建的（自带 LICENSE 或 README 的初始提交），本地又是 `git init` 新建的，
两边历史互不相干，这时 `git pull` 会报 `refusing to merge unrelated histories`，`git push` 会报 `fetch first`。

处理办法：

```bash
git fetch origin
git merge origin/main --allow-unrelated-histories -m "合并远程仓库初始提交"
# 没冲突的话直接推
git push -u origin main
```

有冲突就按「情况 B」改文件、`git add`、`git commit`，再 push。

### 情况 E：`ssh: Could not resolve hostname github.com`（网络/DNS 问题）

这个报错**不是 Git 配置问题**，是电脑当时连不上网 / DNS 解析不了 github.com。常见于：

- 网络刚切换（比如刚开热点给小车用）、Wi-Fi 掉线、VPN 切换；
- 校园网需要登录认证，认证过期了。

排查顺序：

```bat
ping github.com                 :: 能 ping 通说明网络基本正常
ssh -T git@github.com           :: 能出 "Hi 用户名!" 说明 SSH 正常
nslookup github.com             :: 看 DNS 能不能解析
ipconfig /flushdns              :: 刷新 DNS 缓存
```

- 能上网、SSH 也正常：直接再 `git push` 一次即可（多半是网络闪断）。
- DNS 解析失败：换成公共 DNS（8.8.8.8 或 114.114.114.114），或重新连一次网络/VPN。
- 用浏览器打不开 github.com：先解决网络，Git 这边不用改。

## 6. 千万别做的事

- **不要**提交 `__pycache__`、`.tmp`、日志、模型权重（`.gitignore` 已经挡住了）；
- **不要**把大文件提交进去：`docs/` 里的 PDF（两份共 27MB）、`*.pt` 模型权重、视频、压缩包——
  **这些只放本地或网盘，不要进 Git**（`.gitignore` 里已经忽略 `docs/*.pdf`、`*.pdf`、`*.pt`）；
- **不要**随便 `git push -f`（强推会覆盖别人的提交）；
- **不要**把密码、密钥、`.pem` 文件提交上去；
- 提交前先 `git status` 看一眼，确认没有多出来的文件。

> 判断标准：单个文件超过 **1MB** 就先想一下该不该进仓库；超过 10MB 一律不进。

## 7. 如果上传了不该传的文件

### 7.1 只是刚 add / commit，还没 push

```bash
# 只从 Git 里移除，本地文件保留
git rm --cached 文件名
git commit -m "移除不该上传的文件"
```

如果是大目录，用通配符：`git rm -r --cached docs/*.pdf`

### 7.2 已经 push 了，而且是大文件（历史里已经存在）

光 `git rm --cached` 只能让以后不提交，**历史里还有，仓库体积不会变小**，需要重写历史：

```bash
# 1. 先把文件从所有历史提交里删掉（只改历史，本地文件保留）
git filter-branch -f --index-filter "git rm -r --cached --ignore-unmatch 'docs/*.pdf'" --prune-empty -- main

# 2. 清掉本地备份引用和垃圾
git for-each-ref --format="%(refname)" refs/original | awk '{print}' | xargs -n1 git update-ref -d
git reflog expire --expire=now --all
git gc --prune=now

# 3. 强推覆盖远程历史（注意：会改写提交哈希）
git push --force origin main
```

> 这一步比较危险，做之前确认仓库里没有别人的提交。不会用的话，最简单粗暴的办法是：
> **在 GitHub 上删掉仓库重新建一个空的，再把本地干净版本推上去。**

### 7.3 确认干净了

```bash
git ls-files -s        # 看当前跟踪的文件
git count-objects -vH  # 看仓库体积（应该很小）
```

## 8. 检查清单（每次 push 前）

```bash
git status          # 确认改的文件都对
git diff            # 确认改的内容都对
git add .
git commit -m "说明"
git pull            # 先同步远程
git push
```
